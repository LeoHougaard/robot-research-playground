# Robot playground acceptance

Advance through these gates in order. Record commands, versions, failures, and evidence. Software checks do not establish physical fit or safe unattended operation.

1. **Software on the development machine.** Run the test suite and the built-in demo. Confirm predictions are committed before measured outcomes, agent claims remain hypotheses, successive generations inherit evidence and files, interruptions preserve incomplete trials, and concurrent supervisors are refused.
2. **Spark admission.** Audit the actual host and existing workloads. Require account leo, ARM64, a working GPU/container runtime, and at least the configured 20 GiB free reserve plus storage needed for selected models. The current audit blocks this gate. Preserve existing workloads. Obtain Leo's direction before deleting data or changing host configuration.
3. **Real sandbox.** Run generated Python in the pinned offline container. Test filesystem writes, prohibited network access, missing devices/Docker credentials, memory exhaustion, fork attempts, stdout flooding, timeouts, malicious artifact paths and oversized outputs. Demonstrate cleanup and preserved originals. Configuration tests on Windows are insufficient for this gate.
4. **Local model qualification.** Verify the chosen model produces valid structured tool calls, can observe and complete a small simulation experiment, recovers from a rejected action, and preserves a usable artifact for its successor. Benchmark inference memory and latency. A listed model endpoint does not prove these behaviors.
5. **Mechanical fit.** Print coupons first. Check real servo body and stock horn dimensions against supplied vendor drawings and STEP discrepancies. Check gripper travel, caster height, wheel traction and balance, tether clearance, and all screws. Inspect assembled movement with motor power disconnected.
6. **Electronics on the bench.** Verify UART levels, shared signal reference, power supply and fuse sizing, default-off actuator power switch, physical E-stop, independent hardware watchdog and authorization interlock. Compile firmware with HARDWARE_VERIFIED=0 initially. Verify the disabled binary refuses arming. Measure servo register units, wheel directions, real speed, gripper endpoints, current and temperature limits before enabling the gate in a reviewed firmware build.
7. **Camera acceptance.** Print markers at actual scale, mount the camera rigidly and light the arena evenly. Calibrate at the marker plane. Measure independent heldout reference points and confirm maximum error is within the selected gate. Cover markers and disconnect the camera; actuator power must stop. Robot and object markers need consistent heights or separate calibrated tracking planes.
8. **Bounded physical actions.** With Leo present, authorize short low-speed commands on a raised-wheel fixture, then in the enclosed arena. Kill the Spark process, unplug USB, stop MCU firmware execution, exceed telemetry limits, and trigger E-stop. Verify actual motor power goes off, including when Spark and MCU software cannot respond. A restart stays disarmed.
9. **Endurance.** Progress through 15 minutes, one hour, and 24 hours of repeated movement and self-resetting tasks. Log temperature, power, missed feedback, camera age, cable winding, loss of grip and required rescues. A run that needs manual reset does not pass unattended acceptance.
10. **Research run.** Enable a bounded 72-hour run, then one week. Require prediction accuracy on unfamiliar trials, replayable evidence, inherited working programs and a concise findings digest. Stop on failed health checks, insufficient disk reserve or repeated agent failures. Resume only after the cause is understood.

Physical firmware remains gated and no hardware was tested during project construction. Same-host containers and GPU drivers reduce risk but do not guarantee zero damage or zero service disruption. Generated GPU programs remain disabled in V1.
